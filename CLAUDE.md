# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

HackYeah 2026 project. Currently only a backend exists: FastAPI (Python 3.13) + async SQLAlchemy 2.0 (asyncpg) + Alembic, on PostgreSQL 17, orchestrated with Docker Compose. There is no test suite, linter config, or frontend yet.

## Setup & commands

Two env files are required (both gitignored):
- `cp .env.example .env` — Postgres credentials/host, app name, debug, ports (used by compose and the backend).
- `cp backend/.env.example backend/.env` — JWT settings. `JWT_SECRET_KEY` has no default on purpose; the app refuses to start without it.

Run everything (db → one-shot `migrate` job running `alembic upgrade head` → `backend` on :8000):
```
docker compose up --build
```
API docs at `http://localhost:8000/docs`; `GET /health` checks DB connectivity.

Running the backend locally (outside Docker), from `backend/`:
```
pip install -r requirements.txt
uvicorn app.main:app --reload
```
`Settings` reads `.env` and `../.env` relative to the **current working directory**, so run from `backend/`. The root `.env` sets `POSTGRES_HOST=db` (the compose service name); override with `POSTGRES_HOST=localhost` when running on the host against the compose db (`docker compose up db`).

Migrations (from `backend/`, or via `docker compose run --rm migrate alembic ...`):
```
alembic upgrade head
alembic revision --autogenerate -m "describe change" --rev-id 0003
alembic upgrade head --sql      # offline: print SQL only
```
Revision IDs are sequential hand-picked strings (`0001`, `0002`, …) — pass `--rev-id` with the next number. Filenames are timestamp-prefixed via `alembic.ini`'s `file_template`.

## Architecture (`backend/app`)

Layering: `routers` (HTTP) → `services` (business logic) → `models` (SQLAlchemy ORM), with `schemas` (Pydantic) for request/response shapes.

- **Config** — `core/config.py`: a single cached `settings` object (pydantic-settings). `database_url` is computed from the `POSTGRES_*` vars. Alembic's `env.py` reads the DB URL from here too; `alembic.ini` deliberately has no URL.
- **DB** — `db/session.py` provides the async engine and the `SessionDep` annotated dependency (one `AsyncSession` per request, `expire_on_commit=False`, `autoflush=False`). `db/base.py` defines `Base` with a constraint **naming convention**, so autogenerated migrations get stable names (e.g. `pk_users`, `uq_users_email`).
- **Models** — every new model must be imported in `models/__init__.py`, or Alembic autogenerate won't see it. Tables use plural names (`users`; `user` is reserved in Postgres) and `Identity(always=True)` primary keys named `<entity>_id`.
- **Services raise domain exceptions, routers translate them**: e.g. `services/auth.py` raises `EmailAlreadyRegisteredError` / `InvalidCredentialsError` / `InvalidRefreshTokenError` (subclasses of `AuthError`), and `routers/auth.py` maps them to 409/401. Services don't raise `HTTPException`.
- **Auth flow**:
  - `/auth/register` and `/auth/login` return the access token in the JSON body and set the refresh token as an HttpOnly cookie scoped to path `/auth`.
  - `/auth/refresh` reads that cookie and returns a new access token. The refresh token is not rotated.
  - Protected routes use `CurrentUserDep` (`dependencies.py`), which validates an `Authorization: Bearer <access token>` header and returns 401 (not FastAPI's default 403) on failure.
  - JWTs (`core/security.py`) carry `sub` = user id and a `type` claim (`access`/`refresh`), and decoding enforces the expected type.
- **Passwords** — Argon2id with an explicit per-user hex salt stored in `users.salt`; the PHC hash string also embeds it. Hashing and verification run via `run_in_threadpool` so they stay off the event loop. Login verifies against `DUMMY_PASSWORD_HASH` for unknown emails to avoid timing-based user enumeration.
- **Emails** are normalized (stripped + lower-cased) in the Pydantic schema, so DB lookups and the unique constraint are effectively case-insensitive.
